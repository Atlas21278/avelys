# Internationalisation (FR/EN)

Source : Master Spec §5, §17, §54.2, §54.3 ; ADR-0003, ADR-0004 ; DEC-21 (slugs EN traduits). Mis en place par VTC-013.

## Routage

| Élément            | Choix                                                                                                                                        |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Bibliothèque       | next-intl (`src/i18n/`)                                                                                                                      |
| Locales            | `fr` (défaut), `en`                                                                                                                          |
| Préfixe            | `as-needed` : FR sans préfixe (`/flotte`), EN sous `/en` (`/en/fleet`) ; `/fr/…` redirige (307) vers `/…`                                    |
| Slugs EN           | Traduits (DEC-21), table `pathnames` de `src/i18n/routing.ts` ; une URL EN avec un slug FR (`/en/flotte`) redirige vers le slug EN           |
| Détection          | **Aucune** : l'URL seule fixe la langue ; `/` sert toujours le français, quel que soit `Accept-Language`. Pas de cookie de langue.           |
| Changement         | Sélecteur de langue (`src/components/locale-switcher.tsx`) : liens simples vers la même page dans l'autre langue, sans JavaScript nécessaire |
| Fuseau d'affichage | `Europe/Paris` (stockage UTC)                                                                                                                |
| Hors site localisé | `/api`, `/design` (planche interne, FR), `/admin` (back-office, FR) : exclus du proxy (`src/proxy.ts`)                                       |

Les clés de `pathnames` sont les chemins internes, c'est-à-dire les dossiers sous `src/app/[locale]/`. Table actuelle (pages créées par leurs propres tickets) :

| Interne (FR)        | EN                 |
| ------------------- | ------------------ |

| `/flotte`           | `/en/fleet`        |
| `/a-propos`         | `/en/about`        |
| `/contact`          | `/en/contact`      |
| `/reservation`      | `/en/booking`      |
| `/compte`           | `/en/account`      |

Pages légales ajoutées par VTC-018 (contenu provisoire). Landing pages : slugs à ajouter à la table par leurs tickets (EPIC-14). Toute entrée de la table doit avoir sa page (`src/i18n/routes.test.ts`), sauf `/compte` (EPIC-13), explicitement en attente.

## Messages

- Catalogues `src/i18n/messages/fr.json` (référence) et `en.json`, un espace de noms par page ou composant.
- Aucun texte d'interface en dur dans le site public : `getTranslations` (serveur) ou `useTranslations`.
- Clés typées : `src/i18n/next-intl.d.ts` déclare le catalogue FR ; une clé inexistante ne compile pas.
- `src/i18n/messages.test.ts` vérifie que FR et EN ont exactement les mêmes clés, toutes non vides.
- Exception : la planche `/design` (interne, `noindex`, absente en production) reste en français en dur.

## Liens internes

Utiliser `Link`, `redirect`, `getPathname` de `src/i18n/navigation.ts` (jamais `next/link` avec un chemin écrit à la main) : le slug et le préfixe de la locale sont appliqués automatiquement.

## SEO

- `<html lang>` suit la locale (`src/app/[locale]/layout.tsx`).
- Chaque page déclare `alternates: localeAlternates(<chemin interne>, locale)` dans `generateMetadata` : `canonical` + `hreflang` `fr`, `en` et `x-default` (→ FR), réciproques.
- Les URL absolues sont résolues par rapport à `APP_URL` (`metadataBase`) **à l'exécution** : les pages publiques sont rendues à la demande, une même image sert staging et production.
- Les en-têtes `Link` hreflang du proxy next-intl sont désactivés (source unique : la Metadata API).

## 404

- Chemin inconnu sous une locale (`/inconnu`, `/en/unknown`) : `src/app/[locale]/not-found.tsx`, traduit, statut 404.
- Premier segment qui n'est pas une locale (hors proxy, ex. `/admin` tant que le back-office n'existe pas) : 404 par défaut de Next.js. `src/app/global-not-found.tsx` (option `experimental.globalNotFound`) couvre les URL sans aucune route.
- Limite connue (Next.js 16.3) : le HTML initial d'une 404 est une coquille rendue côté client ; le statut 404 et `noindex` sont bien envoyés.
